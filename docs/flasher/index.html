Install WMR Bridge

Experimental firmware for the ESP32 (classic).

Setting up a Raspberry Pi instead? Use the Raspberry Pi setup page.

This installs the WMR Bridge firmware on an ESP32 board from Chrome or Edge on a desktop, over USB. ESP-IDF is not needed. The board then connects Windows Mixed Reality motion controllers and forwards their input to the companion Android app.

ESP32-S3 and other chips without Classic Bluetooth are not supported. You need a classic ESP32 board with at least 2 MB flash.

Use Both hands for the normal single-bridge install. Flash LEFT and RIGHT to two bridges when one bridge carrying both controllers is losing packets: each bridge then serves one controller, ignores the other, and advertises its own name. LEFT (or RIGHT) also gives a single board a one-command single-hand build for validation.

What you need

  
    
    
  • An ESP32 board with 2 MB flash and a USB data cable.
    • 
    
  • A supported desktop browser with Web Serial:
      
      
        
    • Chrome or Edge on Windows (x64, x86, ARM64) or macOS (Intel x64, Apple Silicon ARM64).
      • 
        
    • Chrome or Edge on Linux x64, or Chromium on Linux ARM/ARM64.
      • 
        
    • Chrome on ChromeOS.
      • 
      
    
      Firefox and Safari do not support Web Serial; mobile browsers (Android/iOS) are unsupported.
    
    • 
    
  • Appropriate USB-to-UART bridge drivers for your board (e.g. CP210x, CH340, FTDI) and serial port permissions on Linux (e.g. dialout or uucp group membership).
    • 
    
  • Nothing else: no Arduino IDE, no ESP-IDF, no Python.
    • 
  


  
Steps

  
    
    
  1. Connect the ESP32 to the computer with the USB cable.
    2. 
    
  2. Click the install button for the image you need: Both hands
      for one bridge, or LEFT / RIGHT for two
      bridges. Then choose the board's serial port. If you see several ports,
      unplug the board and plug it back in to see which one appears.
    3. 
    
  3. Let the installer erase and flash the board. This takes about a minute.
      If it says "Failed to connect", hold the board's BOOT
      button while it retries, and make sure no serial monitor has the port open.
    4. 
    
  4. Use Pair your controllers above: pair the LEFT and/or
      RIGHT controller and watch its packet counter climb. The bridge finds
      them by name and stores their addresses, so later they reconnect on their
      own. Open the log if you need the boot banner: the advertised name tells
      you which image is running, BLE advertising: WMR Bridge
      (both hands), WMR Bridge L or WMR Bridge R.
    5. 
    
  5. If this browser has no Web Serial, open a serial monitor at
      115200 baud instead and put the controller(s) in pairing
      mode within a minute of first boot; the bridge finds and stores their
      addresses, and pressing d starts another search.
    6. 
  


  

    

      Read this before using it. WMR Bridge is experimental
      test firmware, not a finished product. Its BLE service is unauthenticated
      and unencrypted, and the board ships with secure boot and flash encryption
      disabled. Anyone in radio range can receive the controller data.
      See docs/SECURITY.md.
