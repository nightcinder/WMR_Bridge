Install WMR Bridge

Experimental firmware for the ESP32 (classic).

This installs the WMR Bridge firmware on an ESP32 board from Chrome or Edge on a desktop, over USB. ESP-IDF is not needed. The board then connects Windows Mixed Reality motion controllers and forwards their input to the companion Android app.

ESP32-S3 and other chips without Classic Bluetooth are not supported. You need a classic ESP32 board with at least 2 MB flash.

Use Both hands for the normal single-bridge install. Flash LEFT and RIGHT to two bridges when one bridge carrying both controllers is losing packets: each bridge then serves one controller, ignores the other, and advertises its own name. LEFT (or RIGHT) also gives a single board a one-command single-hand build for validation.

What you need

  • An ESP32 board with 2 MB flash and a USB data cable.
  • Chrome or Edge on Windows (x64, ARM64), macOS (Intel, Apple Silicon ARM64) or Linux (x64, ARM64). Firefox and Safari do not support Web Serial; mobile browsers (Android/iOS) are unsupported.
  • Appropriate USB-to-UART bridge drivers for your board (e.g. CP210x, CH340, FTDI) and serial port permissions on Linux (e.g. dialout group).
  • Nothing else: no Arduino IDE, no ESP-IDF, no Python.

Steps

  1. Connect the ESP32 to the computer with the USB cable.
  2. Click the install button for the image you need: Both hands for one bridge, or LEFT / RIGHT for two bridges. Then choose the board's serial port. If you see several ports, unplug the board and plug it back in to see which one appears.
  3. Let the installer erase and flash the board. This takes about a minute. If it says "Failed to connect", hold the board's BOOT button while it retries, and make sure no serial monitor has the port open.
  4. Open a serial monitor at 115200 baud to check the boot log. The advertised name tells you which image is running: BLE advertising: WMR Bridge (both hands), WMR Bridge L or WMR Bridge R.
  5. On first boot, put the controller(s) this image serves into pairing mode within a minute. The bridge finds them by name and stores their addresses. Later they reconnect on their own.

Read this before using it. WMR Bridge is experimental test firmware, not a finished product. Its BLE service is unauthenticated and unencrypted, and the board ships with secure boot and flash encryption disabled. Anyone in radio range can receive the controller data. See docs/SECURITY.md.

Where this firmware comes from

This page and the images next to it are built from nightcinder/WMR_Bridge by the firmware workflow. Do not flash an image from anywhere else. The build metadata (variant, flag values, commit, BTstack commit, ESP-IDF version) is in build-info*.json next to the image.
